# Структура переформульованої статті для ІК НАН

## Робоча назва

**«Архітектура персистентної пам'яті для довгострокових автономних місій з ротацією операторів: дворежимне витягування та сигнал корекції»**

Альтернатива:
**«Підсистема робочої пам'яті автономного агента для забезпечення безперервності управління при зміні операторів»**

## Цільове видання

- Проблеми програмування (ІПС НАН, фахове, Scopus)
- Кібернетика та системний аналіз (Springer, Scopus) — якщо Палагін підтримає
- Збірник праць Інституту кібернетики НАН

## Мова: українська

---

## АНОТАЦІЯ

Автономні агентні системи, що виконують довгострокові місії (години — тижні), потребують підсистеми пам'яті, одиницею витягування якої є оперативне рішення, а не діалоговий обмін або фрагмент коду. Існуючі системи пам'яті для мовних моделей (MemGPT, Mem0, generative agents) організовані навколо діалогових епізодів і не підтримують ключову вимогу реальних місій — безперервність управління при ротації операторів. Ми пропонуємо трирівневу декомпозицію пам'яті (предметна область / робочий процес / оператор) з дворежимним витягуванням: pull-режим для активних сесій та push-режим для фонового оновлення контексту простоюючих задач. Третій внесок — сигнал корекції витягування (retrieval-correction signal): ситуації, коли корекція оператора була б непотрібною, якби система вчасно подала релевантний контекст. Цей сигнал масштабується з автономністю агента і доповнює традиційні метрики нагляду. Архітектура верифікована на платформі з 70+ інструментами та 380M+ записів; базові вимірювання на 304 сесіях підтверджують медіанну вартість ініціалізації 30 115 токенів з 60% надлишковістю контексту.

## 1. ВСТУП: ПРОБЛЕМА БЕЗПЕРЕРВНОСТІ УПРАВЛІННЯ В АВТОНОМНИХ МІСІЯХ

### 1.1. Актуальність

- Автономні агентні системи (БПЛА, наземні роботи, кібернетичні ситуаційні центри) виконують місії тривалістю від годин до тижнів
- При ротації операторів (зміна екіпажу БПЛА, зміна вахти ситуаційного центру) критично зберегти:
  - Які рішення прийнято і чому
  - Які корекції внесено і на підставі якої інформації
  - Які загрози виявлено, але не усунено
  - Який контекст місії залишається актуальним
- Існуючі підходи (dialogue memory, code-RAG, long-context models) не вирішують проблему зміни операторів

### 1.2. Зв'язок із школою кібернетичного управління

- Глушков — Гриценко — Палагін: кібернетичний підхід до людино-машинних систем
- Палагін (2006): онтологічно-керовані системи — формальна структура контролює поведінку системи
- Палагін (2025): еволюційна кібернетика — системи де цілі та обмеження самі еволюціонують
- Наша робота: пам'ять як інфраструктура нагляду — формальна структура забезпечує безперервність контролю при зміні операторів

### 1.3. Постановка задачі

Мета: розробити архітектуру підсистеми пам'яті для автономних агентних систем, що забезпечує:
1. Збереження контексту рішень між сесіями операторів
2. Автоматичне оновлення контексту для простоюючих задач
3. Генерацію сигналу корекції для покращення системи навчання

---

## 2. АНАЛІЗ ІСНУЮЧИХ ПІДХОДІВ

### 2.1. Системи пам'яті для діалогових агентів
- MemGPT (Packer et al., 2023): віртуальне управління контекстом
- Generative agents (Park et al., 2023): епізодична пам'ять для симульованих агентів
- Mem0 (Chhikara et al., 2025): довгострокова пам'ять для LLM
- **Обмеження**: одиниця пам'яті — діалоговий обмін, не оперативне рішення

### 2.2. Витягування для програмних агентів
- RepoCoder (Zhang et al., 2023), CodeRAG (Wang et al., 2024)
- **Обмеження**: витягують фрагменти коду без провенансу рішень

### 2.3. Моделі з довгим контекстом
- Gemini 1.5 Pro (Reid et al., 2024): 1M+ токенів
- **Обмеження**: деградація уваги після ~200K токенів (Liu et al., 2023)

### 2.4. Системи управління знаннями в ситуаційних центрах
- Онтологічно-керовані системи підтримки рішень (Палагін, 2006)
- Системи ситуаційної обізнаності для управління БПЛА
- **Розрив**: жодна з існуючих систем не поєднує онтологічну структуру з дворежимним витягуванням для забезпечення безперервності при ротації операторів

---

## 3. ФОРМАЛІЗАЦІЯ ПРОБЛЕМИ

### 3.1. Три характеристики довгострокових місій
- **Горизонт**: рішення охоплюють дні — тижні (приклад: 105 днів, 1547 PR)
- **Композиційність**: рішення A тижня 2 обмежує рішення B тижня 6
- **Персистентність**: стан місії є спільним між сесіями операторів

### 3.2. Проблема ініціалізації сесії
- Кожна нова сесія оператора починається із завантаження контексту
- Вимірювання: медіана 30 115 вхідних токенів, 60% надлишковість
- При ротації операторів проблема загострюється: новий оператор не має жодного контексту попередника

### 3.3. Формальна постановка
- Pull-режим: зменшення K (зчитувань) і T (токенів) при ініціалізації
- Push-режим: підтримка актуальності контексту для простоюючих задач/місій
- Метрика якості: відсоток корекцій, спричинених недостатнім контекстом

## 4. АРХІТЕКТУРА ТРИРІВНЕВОЇ ПАМ'ЯТІ

### 4.1. Предметний рівень (Domain Layer)
**Оригінал**: юридичний корпус (закони, рішення, регламенти)
**Військове застосування**: оперативна обстановка, картографічні дані, розвіддані, правила застосування сили (ROE), ТТХ техніки

- Семантичне витягування з метаданими (тип загрози, сектор, дата)
- Маршрутизація через єдину підсистему пам'яті замість прямих викликів інструментів

### 4.2. Робочий рівень (Workflow Layer)
**Оригінал**: контекст рішень проєкту (6 джерел)
**Військове застосування**:

| Оригінал | Військовий аналог |
|----------|-------------------|
| Principle ledger (принципи, що порушувались) | Журнал порушень ROE та виправлених помилок |
| Validator definitions | Правила перевірки дотримання ROE/SOP |
| MCP tool contracts | Контракти систем озброєння та сенсорів |
| ADR (Architecture Decision Records) | Рішення командира з обґрунтуванням |
| Git history | Хронологія дій місії |
| Issue tracker state | Стан завдань/цілей місії |

- Гібридне витягування: семантична подібність + фільтри (сектор, тип місії, час)

### 4.3. Рівень оператора (Practitioner Layer)
**Оригінал**: патерни рішень практика з edit-trace pipeline
**Військове застосування**: профіль оператора — типові корекції, стиль управління, зони уваги

- Ніколи не зберігає сирий контент — тільки структуровані абстракції
- При ротації: новий оператор отримує профіль попередника + ключові рішення місії
- Приватність: тільки структуровані резюме, не сирі дані

## 5. ДВОРЕЖИМНЕ ВИТЯГУВАННЯ

### 5.1. Pull-режим (активні сесії)
- При вході нового оператора: запит до всіх трьох рівнів паралельно
- Результат: компактний дайджест замість повного завантаження всього контексту
- Зменшення K (зчитувань) і T (токенів) ініціалізації

### 5.2. Push-режим (фонове оновлення)
- Для простоюючих задач/секторів: планове фонове оновлення
- При відновленні роботи в секторі: контекст актуальний без повторного збору
- **Критично для ротації**: між змінами push-режим оновлює контекст місії новими подіями

### 5.3. Чому необхідні обидва режими
- Pull без push: після тривалої паузи контекст застарілий
- Push без pull: надлишковий контекст при кожній сесії
- Комбінація: push підтримує актуальність, pull фокусує витягування на поточну задачу

### 5.4. Сигнал корекції витягування (Retrieval-Correction Signal)
- Корекція оператора, яка була б непотрібною при наявності правильного контексту
- Приклад: оператор БПЛА коригує маршрут бо не знав про зміну обстановки в секторі — якби push-режим оновив контекст, корекція не знадобилась би
- Цей сигнал — метрика якості підсистеми пам'яті + додатковий сигнал навчання

## 6. РЕАЛІЗАЦІЯ ТА ЕКСПЕРИМЕНТАЛЬНА ВЕРИФІКАЦІЯ

### 6.1. Платформа LEX AI як тестовий полігон
- 70+ MCP-інструментів, 380M+ записів
- 1 547 PR за 105 днів, 1 практик, 0 співробітників
- Аналогія: 1 оператор з максимальною пропускною здатністю = стрес-тест підсистеми пам'яті

### 6.2. Базові вимірювання (304 сесії)
- Медіана вартості ініціалізації: 30 115 токенів
- Медіана надлишковості контексту: 60%
- Зростання CLAUDE.md: 217 символів/день (R² = 0.87)

### 6.3. Цільові показники
- Зменшення до ≤10K токенів ініціалізації
- Зменшення надлишковості до ≤20%

### 6.4. Застосовність до управління БПЛА та ситуаційних центрів
- Зіставлення метрик: токени ≈ час ініціалізації оператора, надлишковість ≈ когнітивне навантаження
- Ротація: час передачі управління як ключова метрика бойової готовності
- Retrieval-correction signal: кожна непотрібна корекція = потенційно запобігнутий інцидент

## 7. ОБГОВОРЕННЯ

### 7.1. Від пам'яті програмного агента до пам'яті бойової системи
- Архітектура агностична до домену — та сама трирівнева декомпозиція працює для юридичного AI та управління БПЛА
- Ключова різниця: вимоги до латентності (мс для БПЛА vs. секунди для юридичного AI)

### 7.2. Еволюційна кібернетика та адаптація пам'яті
- Зв'язок з Палагіним (2025): пам'ять місії як еволюційна система, де контент, пріоритети та структура витягування адаптуються до зміни обстановки
- Push-режим як механізм еволюційного оновлення

### 7.3. Зв'язок з ontology-controlled systems
- Предметний рівень пам'яті = онтологія домену (Палагін, 2006)
- Робочий рівень = онтологія процесу управління
- Рівень оператора = модель когнітивного профілю

### 7.4. Обмеження
- Верифікація на одній платформі (юридичний AI, не БПЛА)
- Одиничний оператор (потрібна багатооператорна когорта)
- Push-режим ще не реалізований у повному обсязі

---

## 8. ВИСНОВКИ

Запропоновано архітектуру підсистеми персистентної пам'яті для автономних агентних систем, що виконують довгострокові місії з ротацією операторів. Трирівнева декомпозиція (предметна область / робочий процес / оператор) з дворежимним витягуванням (pull + push) забезпечує безперервність контексту управління при зміні операторів. Сигнал корекції витягування надає додаткову метрику якості нагляду, яка масштабується з автономністю агента.

## Зв'язок зі школою Палагіна (для обґрунтування перед ІК)

1. **Палагін (2006)** — онтологічно-керовані системи → предметний рівень пам'яті
2. **Палагін (2020)** — дистрибутивна семантика → embedding pipeline для витягування
3. **Палагін (2023)** — OntoChatGPT → онтологічний контроль виходу агента
4. **Палагін (2024)** — нейромережева + онтолінгвістична інтеграція → гібридне витягування
5. **Палагін (2025)** — еволюційна кібернетика → push-режим як еволюційне оновлення
